# 2026-11-08 개념 공부

## 1. 암호화와 해시

### 암호화
원본 데이터를 키를 사용해 알아보기 어려운 암호문으로 바꾸고,
필요할 때 다시 복호화해서 원본으로 되돌릴 수 있는 방식이다.

- 평문(Plaintext): 암호화 전 원본 데이터
- 암호문(Ciphertext): 암호화된 데이터
- 암호화(Encryption): 평문 -> 암호문
- 복호화(Decryption): 암호문 -> 평문
- 키(Key): 암호화/복호화 과정에 사용하는 값

### 해시
입력 데이터를 일정한 길이의 해시값으로 변환하는 방식이다.
정상적인 복호화 과정을 전제로 하지 않는다.

예:
- SHA-256

암호화와 해시의 핵심 차이:
- 원본을 다시 복원해야 하면 암호화
- 원본을 다시 알 필요가 없으면 해시 기반 방식 고려

## 2. 비밀번호와 Salt

비밀번호는 원문을 다시 복구할 필요가 없기 때문에 해시 기반 저장이 적절하다.

Salt는 비밀번호 해싱 전에 사용자별로 추가하는 랜덤값이다.
같은 비밀번호를 쓰더라도 서로 다른 결과가 나오도록 해 미리 계산된 공격을 어렵게 만든다.

비밀번호 저장에는 단순 SHA-256 한 번보다 다음과 같은 전용 방식이 적절하다.
- Argon2id
- bcrypt
- scrypt
- PBKDF2

## 3. 대칭키와 비대칭키

### 대칭키
암호화와 복호화에 같은 비밀키를 사용한다.

장점:
- 빠름
- 대용량 데이터 처리에 적합

주의점:
- 키 관리가 매우 중요함
- 키가 유출되면 암호문을 복호화할 수 있음

대표 예:
- AES
- SEED
- ARIA

### 비대칭키
공개키와 개인키라는 서로 다른 키를 사용한다.

대표 활용:
- 키 교환/보호
- 인증
- 디지털 서명

대표 예:
- RSA
- ECC 계열

## 4. 세션 키

세션 키는 한 번의 통신 연결 동안 임시로 사용하는 대칭키라고 이해하면 된다.

비대칭키 기술로 안전하게 키를 합의하거나 보호하고,
실제 데이터 통신은 빠른 대칭키 세션 키로 처리하는 구조가 많이 사용된다.

## 6. Linux 기본 명령어

### 파일/디렉터리 확인
```bash
ls
```

### 실행 중인 프로세스 확인
```bash
ps -ef | grep postgres
pgrep -a postgres
```

### 서비스 상태 확인
```bash
systemctl status postgresql
```

### 로그에서 특정 문자열 검색
```bash
grep "ERROR" postgresql.log
grep -i "error" postgresql.log
```

### 로그 실시간 확인
```bash
tail -f postgresql.log
tail -f postgresql.log | grep "ERROR"
```

### 특정 포트 사용 프로세스 확인
```bash
ss -lntp | grep 5432
lsof -i :5432
```

기억할 연결:
- ls -> 파일/디렉터리
- ps / pgrep -> 프로세스
- grep -> 문자열 검색
- tail -f -> 실시간 로그
- ss / lsof -> 포트 확인
- systemctl -> 서비스 상태
